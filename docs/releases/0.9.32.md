# Devbox 0.9.32

This was an unpublished qualified candidate, superseded by 0.9.34 after the
additional modal-selection review findings were reproduced and corrected.

This release combines native research and state-efficiency changes with clearer
browser observations and Chrome Bridge 0.2.9. The server remains C++23 and adds
no runtime dependency.

- Research duplicate signatures reuse the Unicode tokenizer and retain five
  working words while preserving significant tokens and exact signature bytes.
- Web-cache admission counts the same compact JSON bytes that are atomically
  written, including conditional HTTP revalidation.
- Windows private-directory validation avoids repeating a deep volume traversal
  while retaining parent, reparse, fixed-drive, token and fresh ACL checks.
- Native UTC formatting uses bounded calendar arithmetic, handles negative epochs
  and four-digit years, and avoids locale-dependent stream formatting.
- Native browser observations expose active dialogs, their controls and scroll
  regions, including a scrolling modal container. The actual browser regression
  covers native, ARIA, shadow-root and whole-dialog scrolling flows on Windows
  and Linux, with fresh observations and owned-session cleanup.
- Chrome Bridge supports an explicit until-revoked grant, surfaces active dialogs,
  and binds grants and individual revocation to the tab displayed in its popup.
  Granting rejects an origin change. Worker shutdown remains a documented end to
  in-memory access; no storage permission or silent grant restoration is added.
- The retained JavaScript and Rust reference implementations update jose to
  6.2.14 and rmcp to 3.8.0, with matching lockfiles.

Component benchmark methodology and limitations are retained in
`research-signature-performance.md`, `private-directory-volume-performance.md`,
`native-utc-formatting.md` and `web-cache-byte-accounting.md` in the parent docs
directory. Their timings are component measurements, not whole-agent latency.

The release workflow requires the full native platform, Android/Termux,
distribution, sanitizer, security, installer and packaging checks. Published
assets retain their source identity, checksum inventory and signed qualification
evidence. Existing versioned releases are not overwritten.
