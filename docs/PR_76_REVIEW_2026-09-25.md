## Verified findings and changes

### Pause before model or tool admission

A concurrent pause could commit between the controller's initial state read and `save(..., "model_admitted"/"tool_admitted")`. The previous save merged the new control flag but overwrote the paused status and pre-admission phase, admitting work despite the pause.

Admission now returns the committed paused record unchanged. Neither model/tool callbacks nor budget charges occur. The pre-admission phase remains safely resumable. Tests interleave real SQLite state operations for both model and granted-tool admission, check unchanged revisions and budgets, and require exactly one dispatch after explicit resume.

### Late drivers must not rewrite dormant runs

The original driver guarded completed, failed, and cancelled runs but still initialized providers for paused, uncertain, or approval-waiting runs. Missing provider configuration could therefore overwrite a dormant run with a new driver failure.

Drivers now proceed only for runnable `ready` or `running` records. Failure publication applies the same restriction while retaining the driver lease, controller lease, and revision compare-and-swap. Three tests preserve the complete public state and event list for dormant runs. Driver startup after resume, approval, or reconciliation also requires a returned `ready` state, addressing the verified out-of-diff CodeRabbit comment about cancelled approvals spawning unnecessary processes.

### Interrupted Responses output must be non-executable in both forms

A completed Responses event followed by a partial SSE frame previously cleared normalized tool calls at `finish()` but retained executable `native_output`. A shared clearing helper now discards both representations and their fragment accumulators on interruption and parser failure. Tests cover both an unfinished line and an unterminated event; repeated finalization remains fail-closed. The interrupted result also clears residual text, preserving the stricter concurrent refinement. Previously emitted streaming callbacks cannot be retracted.

### Terminal event and response status must agree

A `response.failed` or `response.incomplete` envelope could carry nested `status: completed`. The parser now rejects every disagreement between the terminal event suffix and nested response status before accepting output. Tests cover all six inconsistent pairs and retain valid completed, incomplete, and failed responses with and without an optional Responses `[DONE]` sentinel.

### Chat tool-call collections require arrays

JSON object iteration previously allowed an object containing tool-call-shaped values to stand in for the `tool_calls` array. Streaming and non-streaming Chat Completions now require an array or null. Nullable incremental metadata and usage-only final chunks remain supported and explicitly tested.

These parser checks are defense in depth. They do not establish a demonstrated grant bypass or authorize any new effects.
